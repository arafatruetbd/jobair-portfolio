# PRD — Jobair Portfolio Website

## 1. Product Overview

**Product Name:** Jobair — Professional Portfolio  
**Document Type:** Product Requirements Document (PRD)  
**Primary Goal:** Create a minimalist, professional personal portfolio website that positions Jobair as an experienced **Acumatica ERP & Ticket Operations Specialist** with 4+ years of hands-on experience.

The portfolio should communicate Jobair’s two primary areas of expertise:

1. **Acumatica ERP & Multi-Channel E-commerce Order Processing**
2. **Ticket Operations, Research, Pricing & Inventory Management**

The website should feel polished, credible, simple, and business-focused rather than decorative or overly creative.

---

## 2. Product Objectives

The portfolio should:

- Establish Jobair as a reliable operations specialist.
- Highlight 4+ years of hands-on professional experience.
- Present Acumatica ERP as the primary specialization.
- Present ticket operations as a second specialized area.
- Make Jobair’s experience easy to scan within 10–15 seconds.
- Show familiarity with multiple platforms without making the UI visually crowded.
- Encourage recruiters, clients, or employers to contact Jobair.
- Work well on desktop, tablet, and mobile.
- Be lightweight, fast, and accessible.

## 5. Visual Direction

### Design Style

The website should use a **minimal corporate portfolio style** with:

- White or near-white background
- Dark navy typography
- Muted green as the primary accent
- Soft gray borders
- Light card backgrounds
- Minimal shadows
- Rounded corners used carefully
- Generous spacing
- Strong typographic hierarchy

Avoid:

- Heavy gradients
- Excessive animation
- Large decorative illustrations
- Bright multi-color UI
- Too many icons
- Glassmorphism
- Overly rounded “startup SaaS” design
- Dense dashboard-style layouts

### Suggested Color Palette

| Token | Value |
|---|---|
| Background | `#FFFFFF` |
| Surface | `#F8FAF9` |
| Primary Text | `#0B1B35` |
| Secondary Text | `#5F6B7A` |
| Accent Green | `#16845B` |
| Accent Green Hover | `#116C4A` |
| Border | `#E4E9E7` |
| Soft Accent Background | `#EEF8F3` |

### Typography

Recommended fonts:

- Inter
- Manrope
- DM Sans
- Plus Jakarta Sans

Typography should use:

- Bold / semibold headings
- Regular paragraph text
- Small uppercase eyebrow labels where useful
- Comfortable line-height
- No oversized display typography

# 14. Interaction Requirements

Animations must be subtle.

Allowed:

- 150–250 ms hover transitions
- Button hover state
- Card border hover
- Small arrow movement
- Smooth anchor scrolling
- Small fade-in on viewport entry

Avoid:

- Parallax
- Large-scale motion
- Cursor effects
- 3D animation
- Auto-playing sliders
- Excessive scroll animation

---

# 15. Accessibility

The website should target WCAG AA where practical.

Requirements:

- Sufficient text contrast
- Minimum 16 px body text
- Visible keyboard focus states
- Semantic heading hierarchy
- Meaningful image `alt` attributes
- Buttons and links clearly distinguishable
- Navigation keyboard accessible
- Do not communicate status using color alone
- Respect `prefers-reduced-motion`

---

All portfolio copy must:

- Use concise professional English.
- Avoid exaggerated claims.

---

# 23. Privacy & Confidentiality Requirements

Because this portfolio describes operational work involving commercial systems:

- Never show customer personal data.
- Never show order numbers tied to real customers.
- Never show private pricing sheets.
- Never show login information.
- Never expose company-specific confidential SOPs.
- Blur or replace sensitive data in screenshots.
- Use recreated/sample data when needed.
- Do not imply affiliation or endorsement by Acumatica, Amazon, AXS, Ticketmaster, or other platforms.

---

# 24. Acceptance Criteria

The first production version is complete when:

- Header navigation works.
- Hero clearly introduces Jobair and his specialization.
- 4+ years of experience is visible.
- All four portfolio areas are represented.
- Acumatica appears as the primary portfolio item.
- AXS and Ticketmaster are separately represented.
- Multi-platform ticket operations are represented.
- CTA buttons navigate correctly.
- Contact details are accessible.
- Layout is responsive across desktop, tablet, and mobile.
- UI remains visually minimal.
- Accessibility basics are implemented.
- Metadata is configured.
- No placeholder text remains.
- No unsupported or unverified claims are displayed.
